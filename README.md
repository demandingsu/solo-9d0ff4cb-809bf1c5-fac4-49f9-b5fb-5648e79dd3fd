# 馆藏成套器物核对工具

供馆藏编目员核查**成套器物目录是否漏录、错挂**的网页工具：
输入藏品列表页地址，工具沿同站分页抓取套件与器件详情，双向核对
「套件列出的器件编号」与「器件标注的所属套件」，并给出带来源链接的核对报告。

针对**核对途中目录仍在更新**的场景：首轮抓取结束后，工具会**采集后复读**本轮
成功读取的全部列表页、套件及器件详情，对照分页与详情链接、馆藏编号和所属关系；
若复读失败或内容发生变化，说明本轮数据可能混有两个版本，报告标记「无法确认」
并列出问题地址，不展示确定结论；页面均未变化时沿用原核对结果。

技术栈：Python + FastAPI + BeautifulSoup；Docker Compose 一键启动核对工具与本地样本目录站，全程离线可用。

## 快速开始

```bash
docker compose up --build
```

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| 核对工具 | http://localhost:8000 | 输入列表页地址，查看核对报告 |
| 样本目录站 | http://localhost:8001 | 正常目录入口（首页即目录第 1 页） |
| 样本目录站·故障演示 | http://localhost:8001/broken-1.html | 含失效详情链接的残缺目录 |
| 样本目录站·更新演示 | http://localhost:8001/mutable/ | 翻页抓取途中目录被更新（见下文） |

首页已预填样本站地址，点击「开始核对」即可；全部来源链接均可在浏览器离线打开对照。

## 核对规则（判定口径）

| 类别 | 判定 |
| --- | --- |
| **缺记录** | 套件列出了某器件编号，但完整抓取后目录中不存在该编号的器件详情 |
| **归属不符** | 器件标注的所属套件与「列入它的套件」对不上（含所属套件未收录、套件未列入该器件、器件未注明所属套件、编号与详情页不符） |
| **未被套件列入** | 器件既未注明所属套件，也没有任何套件将其列入 |
| **无法确认（抓取失败）** | 存在抓取失败 / 抓取截断时，未找到的器件编号**不直接判为缺记录**，单独列出，报告标记「核对不完整」并附失败地址 |
| **无法确认（目录更新）** | 采集后复读发现页面内容变化或复读失败时，本轮数据可能混有两个版本：列出问题地址，本轮标为「无法确认」，**不展示确定的缺记录、归属不符、未被套件列入及一致数量** |
| **跨页重复** | 同一详情页被多个分页重复链接时只抓取一次、只统计一次，报告中列出重复引用情况 |

报告末尾附「套件 → 器件」「器件 → 套件」双向对照明细，便于人工复核。

## 采集后复读（应对核对途中目录更新）

编目员核对正在更新的目录时，翻页途中读到的套件和器件详情可能来自两个版本，
把各自正确的归属报成错挂。为此，抓取分两步：

1. **首轮抓取**：沿分页抓取列表页、套件与器件详情，并为每个成功读取的页面
   记录内容快照（页面类型、分页链接、详情链接、馆藏编号、套件器件清单、器件所属套件）。
2. **采集后复读**：重新读取本轮成功读取的每一页，与首轮快照逐页对照：
   - 页面均未变化 → 报告沿用原核对结果，标记「核对完整」；
   - 任一页面复读失败或内容变化 → 报告列出全部问题地址（含引用它的页面与变化说明），
     本轮标为「无法确认」，缺记录、归属不符、未被套件列入与一致数量等确定结论一律从略，
     待目录稳定后重新核对。

## 样本数据内置的问题（用于验证工具）

正常目录（`http://localhost:8001/`）：

- `瓷-104`：套件 套-001 列出，但目录中无详情页 → **缺记录**
- `瓷-202`：套件 套-002 列入，器件页却标注属「套-003」（未收录）→ **归属不符**（双向各一条）
- `瓷-203`：器件页标注属 套-002，但 套-002 未将其列入 → **归属不符**
- `瓷-301`：无所属套件，亦无套件列入 → **未被套件列入**
- `瓷-101`：同时出现在目录第 1、2 页 → **跨页重复**，只算一次

残缺目录（`http://localhost:8001/broken-1.html`）：

- `瓷-901` 详情页 404 → 报告标记**核对不完整**、列出失败地址，该器件记为**无法确认**
- `瓷-902` 无详情页，但因存在抓取失败 → **无法确认**，不判缺记录

更新演示目录（`http://localhost:8001/mutable/`）：

- 样本站对 `/mutable/` 下的页面，前 4 次请求返回**更新前**版本，之后返回**更新后**版本
  （可用环境变量 `MUTABLE_FLIP_AFTER` 调整），模拟翻页抓取途中目录被更新
- 更新内容：`瓷-802` 自 套-101 移入新套件 套-102，并新登记 `瓷-803`；
  两个版本各自核对均一致，只有混读才会报出假「归属不符」
- 对该目录点「开始核对」：首轮抓到两个版本的混合数据，采集后复读发现
  列表页与套件页已变化 → 报告标记**无法确认**并列出问题地址，不展示确定结论
- 再次核对（不重置）：目录已稳定在更新后版本 → 报告**核对完整**、全部一致
- 浏览器打开 `http://localhost:8001/mutable/_reset` 可重置为更新前版本，重新演示；
  `http://localhost:8001/mutable/_status` 可查看当前请求计数与将提供的版本

## 页面识别约定（接入真实目录站）

- 页面类型：`<meta name="page-kind" content="list|suite|item">`（缺省按列表页处理）
- 分页：列表页中的 `<a rel="next" href="...">`；仅跟随**同站**链接
- 详情链接：路径含 `/suite/` 或 `/item/` 的同站链接
- 套件页：编号 `.suite-no`；器件清单位于 `ul.members li`，编号为 `.acc-no`，`<a>` 为可选详情链接
- 器件页：编号 `.acc-no`；所属套件为 `.field-suite` 内的 `.suite-no`（无此标记视为未注明）

## 容器间地址改写

浏览器访问样本站用 `localhost:8001`，而 app 容器内需通过服务名 `sample-site:80` 抓取。
compose 中为 app 设置了：

```
URL_FETCH_REWRITE=localhost:8001->sample-site:80;127.0.0.1:8001->sample-site:80
```

抓取时按此规则改写主机，**报告中的来源链接仍保留原始地址**，浏览器可直接打开。
本机直接运行（非 Docker）时无需设置该变量。

## 本地开发（不用 Docker）

```bash
pip install -r app/requirements.txt
PORT=8001 python3 sample-site/server.py &                 # 样本站（含更新演示目录）
cd app && uvicorn main:app --port 8000                    # 核对工具
```

## 目录结构

```
├── docker-compose.yml      # 一键启动 app + 样本站
├── app/                    # FastAPI 核对工具
│   ├── main.py             # 路由：/ 表单、/check 报告、/healthz
│   ├── crawler.py          # 同站分页抓取（去重、失败记录、地址改写）+ 采集后复读
│   ├── checker.py          # 双向核对逻辑（含「无法确认」判定）
│   ├── models.py           # 数据模型
│   └── templates/          # 表单 / 报告 / 错误页
└── sample-site/            # 本地样本目录站（Python 标准库静态服务器）
    ├── server.py           # 静态页 + 可变目录（请求计数触发目录更新）
    ├── html/               # 列表分页、套件页、器件页（含内置问题数据）
    └── mutable/            # 更新演示目录：v1 更新前 / v2 更新后
```

## 限制

- 仅抓取与起始地址同站（同协议、主机、端口）的页面；单次最多抓取 400 页，超限会在报告中提示「结果可能不完整」
- 抓取为同步执行，适合目录级规模；超大目录请分页核对
- 页面结构需符合上述识别约定
- 采集后复读只重读本轮成功抓取的页面；复读本身也可能读到更新中的中间状态，此时按「无法确认」处理，请稍后重新核对
